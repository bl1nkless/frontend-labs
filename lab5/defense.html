Питання перше: які основні прийоми реалізації гнучкого та адаптивного дизайну фронтенду програмних систем?
Основними прийомами є:
обов’язкове використання метатегу viewport із width=device-width;
заміна фіксованих абсолютних розмірів у пікселях на відносні одиниці вимірювання (rem, em, %, vw, vh, fr);
побудова гнучких сіток макета за допомогою CSS Grid (зокрема функцій repeat, auto-fit, minmax) та CSS Flexbox із переносом рядків flex-wrap;
використання гнучких адаптивних зображень із max-width: 100%, атрибутами srcset і sizes або контейнером <picture>;
та застосування медіазапитів @media із точками зламу (брейкпоінтами) під смартфони, планшети, десктопи і тип вказівного пристрою (hover: none).

Питання друге: які основні способи досягнення кросбраузерності фронтенду?
Основні способи досягнення кросбраузерності:
дотримання стандартів семантичної та валідної розмітки HTML5;
нормалізація або скидання базових стилів браузерів (наприклад, єдиний box-sizing: border-box, скидання appearance: none або підключення Normalize.css);
перевірка таблиць підтримки властивостей за допомогою сервісів Can I use та документації MDN;
використання вендорних префіксів (-webkit-, -moz-) для специфічних властивостей;
застосування умовних конструкцій @supports для підключення резервних CSS-правил (принцип прогресивного покращення та витонченої деградації);
та перевірка роботи сайту в основних браузерних рушіях.

Питання третє: яка основна причина наявності відмінностей між різними браузерами?
Основна причина полягає в тому, що різні браузери розробляються різними компаніями і використовують різні рушії рендерингу HTML/CSS та виконання JavaScript:
Chrome, Edge і Opera працюють на рушіях Blink та V8;
Mozilla Firefox працює на власних рушіях Gecko та SpiderMonkey;
Apple Safari працює на рушіях WebKit та JavaScriptCore.
Кожен із цих рушіїв має власні вбудовані стилі за замовчуванням (User-Agent stylesheet), власні алгоритми апаратного прискорення графіки й 3D-трансформацій і впроваджує нові специфікації W3C та WHATWG у різний час.

Питання четверте: які інструменти для вимірювання метрик ефективності фронтенду Вами використано і які потенційно можуть бути використані?
У цій лабораторній роботі я використав вбудований у Chrome DevTools інструмент Google Lighthouse, за допомогою якого виміряв інтегральні оцінки Performance, Accessibility, Best Practices, SEO та ключові метрики веб-продуктивності Core Web Vitals: First Contentful Paint (FCP), Largest Contentful Paint (LCP), Total Blocking Time (TBT), Cumulative Layout Shift (CLS) та Speed Index.
Потенційно для вимірювання метрик ефективності також можуть використовуватися: вебсервіс PageSpeed Insights (який поєднує лабораторні тести Lighthouse із реальною статистикою користувачів Chrome User Experience Report), вкладки Performance і Network у DevTools, зовнішні сервіси WebPageTest та GTmetrix, а також JavaScript-бібліотека web-vitals та стандартний браузерний Performance API для моніторингу у реальному часі.
